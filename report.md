# QuantumMedx — Analysis Report (Phase 1, PS Q2: Quantum Kernel Classifier)

All numbers below are copied from `results/tables/` (generated by `python main.py`, seeds 0/1/2, transpiler seed 7,
1024 shots per kernel entry, Qiskit 2.5.2 / Aer 0.17.2).

> **Scope warning.** Processor A/B in `processors/` follow the Phase-1 brief (A = 5-qubit line, B = 7-qubit heavy-hex-inspired,
> synthetic depolarising + readout noise, identical gate set `rz, sx, x, cx`). `official_definition` is `false` in the JSON files:
> replace them with the Challenge Kit files and re-run to obtain submission-grade numbers.

## 1. Problem and method
* **PS:** Q2 – Quantum Kernel Classifier. **Data:** Wisconsin breast-cancer diagnostic set (30 features), stratified subsample
  of 40 train / 30 test points per seed, StandardScaler → PCA(5) → MinMax to `[0, s]` (all fitted on train only).
* **Kernel:** `K(x,y)=|⟨0|U(y)†U(x)|0⟩|²` with a ZZ-style feature map (H, P(2x), CX–P(2(π−x_i)(π−x_j))–CX), 1 repetition, 5 qubits.
  Two interaction graphs are compared: **full** (10 pairs) and **linear** (4 nearest-neighbour pairs).
* **Classifier:** SVM on the precomputed kernel; `C ∈ {0.1,1,10,100}` by 4-fold CV on the training kernel only.
  Noisy Gram matrices are made PSD by clipping negative eigenvalues; kernel diagonal is set to 1.
* **Bandwidth `s`:** chosen by train-only CV on the *ideal* kernel (`results/tables/bandwidth_selection.csv`): s = 0.2.
  With s = π (the textbook choice) the ideal kernel concentrates (off-diagonal mean ≈ 0.04); in a pilot check the ideal-kernel classifier then fell to the 63 % majority-class rate on 2 of 3 seeds (full map) and on all 3 seeds (linear map). The training-only CV scan (mean CV accuracy: s=0.1→0.892, 0.2→0.917, 0.3→0.892, 0.5→0.871, 0.8→0.825, 1.2→0.767, π→0.642) selects s = 0.2.
* **Baselines:** ideal statevector kernel; classical RBF- and linear-SVM on the same 5 features.
* **Noise (common benchmark):** 1-qubit depolarising 0.05 % on `sx,x`; 2-qubit depolarising 0.5 % on `cx`; readout P(1|0)=1 %, P(0|1)=2 %; `rz` ideal.
  Identical on A, B and the control.

## 2. Architecture measurements (no execution needed)
Full-entanglement kernel circuit (compute–uncompute), optimisation level 1, same seed. SWAPs are *measured* (transpile with `swap` in the basis).

| Processor | Depth | CX gates | CX with all-to-all | SWAPs | Extra CX from routing | Physical qubits used |
|---|---|---|---|---|---|---|
| All-to-all control (5q) | 49 | 38 | 38 | 0 | 0 | 5 |
| **Processor A** (line) | 81 | 66 | 38 | 12 | 28 | 5 / 5 |
| **Processor B** (heavy-hex-like) | 84 | 61 | 38 | 9 | 23 | 5 / 7 |

Graph statistics: A has diameter 4, mean path 2.0, max degree 2; B has diameter 4, mean path 2.29, max degree 3.
For the **linear** map both processors need 14 CX, depth 31 and **0 SWAPs** — the nearest-neighbour interaction chain embeds into both graphs,
so connectivity differences vanish. (At optimisation level 0, B's trivial layout is *not* a path and costs 4 SWAPs / 28 CX; levels ≥ 1 find the embedding.)
Optimisation levels 2–3 reduce the full map to 58 CX (A) and 53 CX (B), i.e. layout/routing quality is as large an effect as the processor choice.

## 4. Interpretation (evidence-based)
1. **What changed between A and B?** Only the coupling graph (same gates, same noise, same data, same shots). B's degree-3 nodes let the router
   realise the full-entanglement pattern with 9 SWAPs / 23 extra CX instead of 12 SWAPs / 28 extra CX.
2. **The kernel feels it; accuracy does not (at this sample size).** Kernel error is consistently lower on B than on A
   (0.141 vs 0.149; the seed-to-seed SD is only 0.002, so the ~5 % gap is reproducible), but test accuracy is identical (0.933).
   With 30 test points the binomial standard error is ≈ 0.045, so a ≈ 2-point accuracy change is unresolvable. We therefore claim an A/B difference
   in **kernel fidelity and resource cost**, not in classification accuracy.
3. **Routing overhead translates linearly into kernel error.** Relative to the all-to-all control the error grows by 0.046 for +28 CX (A) and 0.0385 for +23 CX (B):
   **≈ 0.00165 per extra CX in both cases** — consistent with a simple "each noisy CX adds a roughly constant error" picture.
   Independently, varying only the transpiler seed on B (59–64 CX) moves kernel error monotonically (`gates_vs_kernel_error.png`; Pearson r ≈ 0.999 within B).
   Processor A gave 66 CX for all 10 seeds, so no within-A correlation can be computed.
4. **Noise sweep** (`noise_sweep.png`, one seed, 24/16 points): as the CX error rises 0 → 2 %, kernel error rises 0.026 → 0.217 (control), 0.286 (B), 0.298 (A);
   at 0.5 % it is 0.085 / 0.116 / 0.122. The ordering control < B < A matches the CX counts 38 < 61 < 66. The off-diagonal spread of the kernel (its useful dynamic range)
   shrinks from 0.190 to 0.107 / 0.078 / 0.072 — noise flattens the kernel toward a constant, a classical-looking failure mode. Accuracy in this sweep is flat
   (0.75–0.81) because 16 test points give 6-point granularity; it is not evidence either way. At p_2q = 0 the residual error 0.026 is shot noise plus readout/1-qubit error.
5. **Connectivity vs. gate set / noise.** Gate sets and noise are identical by construction, so the A–B difference is attributable to connectivity *and* the layout/routing the compiler found,
   not to hardware quality. The linear feature map shows the other side: when the algorithm's interaction graph embeds into the coupling graph, A = B exactly (14 CX, depth 31, identical kernel error).
   Topology matters only for feature maps that do not embed.
6. **Noise hurts the sparse map more in accuracy (0.933 → 0.844) despite fewer gates.** The linear map has half the ideal target alignment (0.14 vs 0.31), so its decision margin is smaller;
   this is a plausible explanation but it is **not tested** here and the SD (0.158) is large.
7. **Quantum vs classical.** On these 5 features the ideal quantum kernel (0.956) and classical SVMs (0.933–0.944) are statistically indistinguishable. No quantum advantage is claimed.

## 5. Limitations and uncertainty
* Placeholder A/B definitions (see scope warning); the official Q2 instance/metrics may differ and take precedence.
* Small data (40/30) and only 3 seeds; accuracy differences below ≈ 5 points are not resolvable. Kernel-error statistics are far tighter than accuracy statistics.
* Synthetic, qubit-uniform noise: no crosstalk, T1/T2, per-qubit variation or non-Markovian effects; `rz` assumed noiseless. Results show *relative* architecture effects, not predictions for real devices.
* Ideal kernel from exact statevectors; noisy kernel from 1024 shots (per-entry binomial SE up to ≈ 0.016).
* Bandwidth chosen on training data from the ideal kernel (not re-tuned per processor); PSD clipping and `K_ii = 1` are modelling choices.
* One finite pair of topologies: this does not establish a general advantage of heavy-hex-like over line connectivity.
* Pearson r ≈ 0.999 in the seed study rests on 10 transpiler seeds with only 5 distinct CX counts for B.

## 6. Reproducibility
`pip install -r requirements.txt && python main.py` (≈ 5 min, CPU). Seeds: data split = shot seed ∈ {0,1,2}; transpiler seed 7 (study: 0–9).
`python main.py --quick` is a ≈ 25 s smoke run. `pytest tests` checks kernel PSD/symmetry and routing ordering. Versions: `results/tables/run_environment.json`.
